# 本体側の不足と実装境界

この作業ではAppDock本体を変更していない。既存のページ表示・pageActions・notifyChanged・Storage・共通情報取得・MCPでチャットの初期機能を構成する。

## 非同期失敗と共通エラー通知

本体の[エラー報告契約](../../AppDock.at365/docs/error-reporting.md)のErrorReporterは本体内部の部品で、一般Appletが任意の本体エラーを報告する公開APIではない。

そのため、Applet内で非同期に完了するCodexの接続・生成失敗を、本体の共通エラー通知へ直接接続する経路はない。現在は会話欄の状態と、既存context.log.errorによる安全な固定説明で確認できるようにした。独自のエラー通知種類や本体APIの改修は追加していない。

将来、共通通知への統合が必要なら、Appletからの失敗報告の所有者・重複抑止・許可・秘密値の境界を公開契約として設計する。現在のチャット機能を止める要因にはしない。

## Codexの寿命

正常停止ではAppletが所有するApp Serverのpipeを閉じ、終了を待つ。応答しない場合に限り、その子プロセスを終了する。

親プロセスが後処理せず終了した場合の回収は、採用版Codexのpipe切断時の動作を実機で確認する。本体がCodexの子孫を一括回収する新APIは追加していない。確認条件と実測結果は[検証記録](../VERIFICATION.md)へ記載する。
